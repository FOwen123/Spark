# Decisions

Choices made where the spec left room. Each entry says what was chosen and why.

- **Desktop shell loads the UI over HTTP.** The Tauri app starts `spark-server` in-process on a random local port and points its window at it, so the desktop and browser builds share one transport and one code path. The built web UI ships as a bundle resource (`tauri.bundle.json`), which keeps `cargo build` working before `web/dist` exists.
- **Vite assets live under `/static`.** `/assets/<hash>` is reserved for document assets served by the server.
- **Designs never run script in Spark's pages.** Every response carries `Content-Security-Policy: script-src 'self'`, and the canvas drops SVG event attributes, `javascript:` links and `<script>`/`<foreignObject>` before rendering, because imported or shared files are untrusted markup inside the page that holds the access token.
- **Layers nest at most 100 levels below an artboard.** Layout, export and HTML import recurse once per level, so the core refuses deeper inserts and moves, and won't open a file that is deeper or has a parent loop. Real designs stay far below this.
- **A `.spark` file has one writer.** Each save bumps a counter in the file and checks it first; if another Spark saved in between, the save fails and the editor shows the error instead of overwriting newer work.
- **Document assets are served without the token.** `/assets/<hash>` URLs are content hashes (128-bit), so knowing one is the capability; this lets `<img>` and CSS backgrounds load them on the canvas and in exported code while Spark runs.
- **Google Fonts download without asking.** Designs imported from other tools name Google Fonts families that usually aren't installed, and they should look right on open, as they do in browser-based design tools. The cost is that the first use of a family sends a request (and the machine's IP address) to Google; after that the copy in the config dir is used. Installed fonts win, so nothing is fetched for them. Rust exports without a UI still use only installed and bundled fonts.
- **New files start with one empty 1440×1024 artboard** so the canvas is never blank.
- **Text layers can have fills.** A text node's fills render as its background (HTML import needs this for buttons and badges); text color is the `color` property.
- **HTML import keeps tag semantics only where they change looks**: headings get bold and their default sizes, `b`/`strong`/`i`/`em` merge into text. Other tag defaults (margins, list bullets) are not reproduced; agents are told to style inline.
- **MCP replies are plain JSON** on each POST (Streamable HTTP allows this); `GET /mcp` answers 405, since Spark never pushes server-initiated messages.
- **Agent presence**: working indicators fade 60 s after the agent's last write and agents drop off the list after 10 idle minutes, in addition to `finish_working_on_nodes` and session end. Stdio clients never send DELETE, so timeouts are the backstop.
- **Artboards made by `create_artboard` default to a flex column** with a white fill, 1440 px wide and fit-content tall, so agents can stack sections with `write_html` without positioning.
- **Screenshots render off screen** in a connected UI window (modern-screenshot over SVG foreignObject), independent of camera and culling. Fonts are declared with `@font-face` in CSS so screenshots can embed them.
- **Agents connect over stdio everywhere.** Every agent entry runs `spark mcp` (the relay reads the token from Spark's config dir), so no token is ever written into an agent's config file. The desktop app's own binary doubles as the relay (`<app> mcp`), so no separate CLI install is needed.
- **"VS Code / Copilot" is two targets**: `vscode` edits VS Code's user `mcp.json` (`servers`), `copilot` edits the Copilot CLI's `~/.copilot/mcp-config.json`.
- **The agent panel attaches Spark by flag where the CLI allows it** (`claude --mcp-config`, `codex -c mcp_servers.spark…`); OpenCode, Gemini CLI and Cursor Agent read their own config, so the panel asks to connect them first.
- **Image budget is an estimate.** Providers don't report prices, so each has a default cost per image (editable in Settings) that the monthly budget counts against. Agent-fulfilled requests cost nothing to Spark and don't count.
- **Generated images arrive outside undo history.** The placeholder's creation is the undo step (part of the agent's `write_html` call); the image filling in later is bookkeeping, so undo removes the placeholder rather than leaving an empty one.
- **Keys go to the OS keychain** through the `keyring` crate. `SPARK_KEYRING_FILE` swaps in a private JSON file, used by tests so they never touch a real keychain.
- **ComfyUI uses a built-in minimal text-to-image graph** (checkpoint from the model setting); custom workflows are out of scope for v1.
- **PDF comes from Rust everywhere**, including the desktop app: the node's SVG (generated in Rust) goes through krilla, so PDFs are vector with consistent output on every platform. The webview's print-to-PDF would need per-platform native bindings (WKWebView `createPDF`, WebView2 `PrintToPdf`) for no visible gain; it stays a possible later improvement.
- **Raster exports prefer the UI renderer** (exact browser layout and fonts) and fall back to Rust (SVG → resvg) when no Spark window is connected, which is what `spark export` uses.
- **Headless layout with taffy.** Nodes the UI never measured (files touched only by the CLI or agents, pages nobody opened) get a flexbox/block layout computed in Rust, with text measured using real font metrics, so exports always have geometry. The UI's measurements replace these as soon as it lays the page out.
- **Rust renderers use bundled Geist TTFs** (OFL, license kept next to them) plus system fonts; the web UI uses the WOFF2 builds of the same fonts.
- **Text in SVG export is laid out by Spark** (greedy word wrap with real glyph advances). It closely matches the browser for Latin text; complex scripts and per-character shaping may differ.
- **One window, tabs in the UI.** All open files live as tabs in a single webview, like the browser build. Background throttling is disabled for that window, which covers every document an agent may be working on.
- **Native menus own their Cmd shortcuts in the desktop app.** Undo, redo, duplicate, zoom, export and the agent panel travel from the menu to the UI as commands; the page ignores those key combos in the desktop app (`?desktop`) so nothing runs twice. Cut, copy, paste and select all stay native, which keeps text fields working and fires the canvas's clipboard events.
- **Opening files and links goes through the server.** Deep links, double-clicked `.spark` files, second launches (single instance) and `?open=` in the browser all call the same reveal step: open the file, switch to the linked page, select the linked node, and tell the UI to show it.
